# 메인 · 어바웃 콘텐츠 관리 적용

대상 DB: **MariaDB 5.5.50**. PHP 코드는 기존 PHP 5.4 문법에 맞췄습니다.

## SQL 실행 순서

1. `20260929_site_content_01_create.sql`: 새 테이블 2개 생성
2. `20260929_site_content_02_insert.sql`: 현재 문구 94개와 현재 사진 경로 11개 입력

기존 테이블을 ALTER하거나 데이터를 삭제하지 않습니다. INSERT를 다시 실행해도 이미 있는 행은 덮어쓰지 않습니다. SQL은 사이트 관리자가 직접 실행합니다. 코드에 자동 테이블 생성이나 자동 INSERT는 없습니다.

`InnoDB`, `utf8mb4_unicode_ci`, 짧은 ASCII 기본키, 명시적인 DATETIME 값을 사용합니다. JSON 타입, 생성 컬럼, 최신 UPSERT 문법, DATETIME의 CURRENT_TIMESTAMP 기본값을 사용하지 않습니다.

## 관리자 위치

- **메인 전시** `/manage/main_exhibition_list`: 상단의 메인 문구 관리와 사진 9개 관리
- **멤버 관리** `/manage/member_list`: 파트별 명단 바로 아래 단체사진 PC/모바일 등록·수정
- **어바웃 문구** `/manage/page_content?page=about`: 사이드바와 멤버 관리 상단에서 연결

문구는 기존 애니메이션의 텍스트 구간별로 입력합니다. 제목 안의 PC/모바일 구간이나 아이콘 사이 문구도 각각 입력하며 기존 태그와 줄바꿈 위치는 유지됩니다. HTML은 일반 텍스트로 출력합니다. 메인 스크립트의 서비스 소개와 흐르는 문구, 어바웃의 떨어지는 글자도 포함합니다. 파트별 명단과 멤버·클라이언트 이름은 기존 관리 기능을 사용합니다.

사진은 각각 저장합니다. 초기 경로는 `/@resource/images/...`이며 새 파일은 `/upload/site_content/YYYYMM/`에 저장됩니다. 서버 PHP 계정에 `/upload/` 생성·쓰기 권한이 필요합니다. JPG/PNG/GIF, 각 5MB 이하 및 4,096 × 4,096px 이하를 허용합니다. PHP의 `upload_max_filesize`, `post_max_size`도 파일 용량 이상이어야 합니다. 기존 파일은 교체 시 삭제하지 않습니다.

메인 1~9번은 원래 `bento01.jpg`~`bento09.jpg`이며 5번이 중앙 단체사진입니다. 어바웃 단체사진은 `team-1.jpg`/`team-1.png`로 시작합니다. 두 페이지의 사진 관리는 독립적입니다.

## 적용 특성

프론트 CSS 파일은 수정하지 않았습니다. 기존 태그·클래스·모션 출력 구조를 유지하고 텍스트/이미지 값만 연결했습니다. 메인 중앙 사진은 기존 CSS의 고정 배경 URL 대신 같은 요소에 DB 이미지 URL을 지정합니다. 메인 스크립트는 기존 HTML 렌더러에 서버에서 이스케이프한 문구를 전달받습니다.

일반 컨트롤러는 기존 `head.php`를 사용합니다. `common.php`를 추가로 include하지 않습니다. SQL 설치 전에는 기존 문구와 사진이 기본값으로 나오며, 관리자에는 초기 설정 안내가 표시됩니다.

문구 저장은 전체 트랜잭션과 행별 revision 검사로 다른 관리자의 수정을 덮어쓰지 않습니다. 사진에도 revision을 적용합니다. 로그인·CSRF·입력 형식·이미지 내용 검증을 포함합니다.

## 검증

- 격리된 로컬 **MariaDB 5.5.50**에서 CREATE/INSERT 실행, 재실행 시 수정값 보존, UTF-8 초기값 일치 확인
- PHP 5.4 문법 파서 검사 및 PHP 8.4 테스트 런타임에서 렌더링·저장 동작 검사 (운영 PHP 5.4 런타임 직접 실행은 아님)
- 초기 DB 값으로 렌더링한 메인/어바웃의 태그·클래스·텍스트를 원본과 비교: 일치
- 서비스 모션에 전달되는 HTML을 원본과 비교: 일치
- HTTP 저장 테스트 15건: 로그인, CSRF, 누락/초과 입력, 특수문자 이스케이프, 빈값, 충돌 시 전체 롤백, 실제 이미지 업로드, 위장 이미지 거절, 기존 사진 유지, 단체사진 PC/모바일 교체

운영 DB에는 접속하거나 SQL을 실행하지 않았습니다. 운영 서버 파일 배포와 SQL 실행 후 관리자에서 저장하고 프론트를 새로고침하여 확인해주세요.
